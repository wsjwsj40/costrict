# DiCode 技能市场完善规划

> 状态：待确认
> 范围：`apps/dicode-vscode`（VS Code 扩展 + Webview）
> 日期：2026-11-18

## 1. 现状

### 1.1 入口与链路

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 入口 | `webview/app.tsx` 顶栏「Skill 市场」 | 切到 `skills` 子页，并发送 `listSkills` |
| 列表 | `webview/Subpages.tsx:23` `SkillList` | 搜索、全部/已启用筛选、启用开关、空状态 |
| 导入 | `webview/app.tsx` 右上角「导入」 | 发送 `importSkill` |
| 消息处理 | `extension.js:1014-1040` | `importSkill` / `listSkills` / `setSkillEnabled` |
| 导入实现 | `extension.js:30-60` `importLocalSkill` | 校验 `SKILL.md`，复制到 `<workspace>/.agents/skills/<目录名>` |
| 测试 | `test/skill-import.test.js` | 覆盖导入成功、同名不覆盖、导入后刷新 |

### 1.2 当前能力

- 技能来源：Codex app-server 的 `skills/list`（`cwds: [workspace]`, `forceReload: true`）。
- 技能启停：Codex `skills/config/write`（`{ path, enabled }`）。
- 技能导入：仅支持选择本地文件夹，要求 `SKILL.md` frontmatter 含 `name` 和 `description`，拒绝符号链接与同名目录。
- 展示字段：`name`、`description`、`path`、`scope`、`enabled`、`pluginId`（前端按 `user/repo/system/admin` 映射来源文案）。

**结论：当前页面本质是「本地已安装技能管理器」，「市场」还缺少发现、详情、安装、更新、卸载等能力。**

### 1.3 现存问题

按优先级排列：

1. **登录耦合与加载状态缺失**：`listSkills` 依赖 `ensureClient()`，未登录时只能看到一条错误；加载态靠字符串「正在加载…」模拟，没有骨架屏或重试入口。
2. **错误反馈不完整**：`skillsError` 只覆盖列表失败；启停失败会走通用 `error` 消息，而技能页不展示该消息，用户可能看不到失败原因。Codex 返回的分条 `errors` 也被压缩成「部分技能加载失败」。
3. **无详情页**：看不到 `SKILL.md` 内容、来源、完整路径和文件列表，无法判断技能是否值得启用。
4. **无删除/卸载/更新**：导入后只能启停，残留目录需要用户手动删除；重复导入只能得到「目录已存在」。
5. **启停不可靠**：非乐观更新、无逐项 pending、无失败回滚；快速点击可能并发写入。
6. **导入能力有限**：只支持文件夹，不支持压缩包/单文件；无覆盖、重命名、进度、体积与文件数限制。
7. **可发现性弱**：只有「全部/已启用」两个筛选项，没有来源分组、排序、分类或推荐；数量统计不完整。
8. **刷新时机少**：仅打开页面、导入、启停后刷新；外部变更不可见，也没有手动刷新。
9. **数据模型未定义**：前端以 `any` 处理，以 `path` 作为 key，字段和错误结构不稳定。
10. **文案与语义不符**：入口叫「Skill 市场」，实际是本地管理；未登录用户进入后体验不完整。
11. **可访问性与响应式细节**：列表行不可点击/不可键盘聚焦，窄宽度样式只做了简单适配。

## 2. 目标

### 2.1 产品目标

- 让用户能**发现、判断、安装、启停、更新、卸载**技能，形成闭环。
- 本地技能管理先做到可靠、可解释、可恢复；再接入远程技能目录。
- 保持与 Codex 技能机制兼容，不引入第二套技能格式。

### 2.2 方案选择

| 方案 | 内容 | 依赖 | 建议 |
| --- | --- | --- | --- |
| A | 完善本地技能管理（详情/删除/刷新/错误处理/交互） | 仅扩展 | **本轮推荐** |
| B | 接入远程技能市场（浏览/安装/更新） | 需要服务端目录接口或静态目录托管 | 后续 |
| C | A + B 一次完成 | 需要 B 的前置条件 | 范围大，不建议本轮 |

**建议本轮先做方案 A。** 原因：仓库内没有技能市场服务端接口，B 的接口、鉴权、托管与审核流程尚未确定；而 A 的缺陷已经直接影响现有功能可用性。A 完成后，B 可以复用同一套数据模型、详情页与安装流程。

## 3. 阶段一：本地技能管理（本轮建议实施）

### 3.1 数据与消息协议

在 Webview 侧定义统一的 `Skill` 模型（建议新增 `webview/skills.ts`）：

```ts
type Skill = {
  id: string          // 稳定标识，优先 path，其次 scope + name
  name: string
  description: string
  path?: string
  scope?: 'user' | 'repo' | 'system' | 'admin' | 'unknown'
  enabled: boolean
  pluginId?: string
  source?: 'local' | 'imported' | 'market'
}
```

扩展与 Webview 的消息约定：

| 方向 | 消息 | 说明 |
| --- | --- | --- |
| Webview → 扩展 | `listSkills` | 拉取列表 |
| | `importSkill` | 导入本地文件夹 |
| | `setSkillEnabled` | `{ id/path, enabled }` |
| | `getSkillDetail` | `{ id/path }`，返回元数据 + `SKILL.md` + 文件列表 |
| | `openSkillFile` / `revealSkill` | 打开 `SKILL.md` / 在资源管理器中显示 |
| | `deleteSkill` | `{ id/path }`，仅允许可管理来源 |
| 扩展 → Webview | `skills` | `{ skills, errors, loading }` |
| | `skillsDetail` | `{ skill, content, files }` |
| | `skillsError` | `{ message, path? }` |
| | `skillsNotice` | 导入/删除/启停成功的轻提示 |

保持对旧消息的兼容，避免一次性大改。

### 3.2 列表页

- 增加手动刷新按钮与刷新中的禁用态。
- 增加加载骨架、错误状态与「重试」。
- 筛选：全部 / 已启用 / 已禁用；按来源（工作区 / 个人 / 组织 / 系统）分组或筛选。
- 显示各来源数量、启用数量；按启用状态与名称稳定排序。
- 搜索范围扩展到来源文案与路径。
- 点击列表行进入详情页；开关仍可独立操作，不触发行点击。

### 3.3 详情页

- 展示名称、描述、来源、完整路径、启用状态。
- 渲染 `SKILL.md`（复用现有 Markdown 渲染与安全链接处理）。
- 展示技能目录下的文件列表（限制深度与数量）。
- 操作：启用/禁用、打开 `SKILL.md`、在资源管理器中显示、删除（仅允许安全来源）。
- 路径安全：只读取已知技能根目录内的文件（例如 `<workspace>/.agents/skills`、用户级技能根目录），拒绝 `..`、符号链接逃逸和任意路径读取。

### 3.4 导入流程

- 保留文件夹导入；校验 `SKILL.md`、frontmatter、体积与文件数上限。
- 同名目录不再直接失败：提供「覆盖 / 重命名 / 取消」选择；覆盖前先备份，失败回滚。
- 导入过程显示进度；成功后刷新列表并提示，可选择跳转详情。
- 压缩包导入（zip）作为可选项，放入阶段二与市场安装共用同一套安全解压逻辑。

### 3.5 启停可靠性

- 乐观更新：点击后立即切换 UI。
- 逐项 pending：写入期间该行开关禁用，避免并发。
- 失败回滚并显示具体原因；成功可静默或轻提示。
- 列表刷新失败时保留上一次有效数据。

### 3.6 删除/卸载

- 删除前弹出模态确认，明确将删除的目录。
- 只允许删除工作区或用户目录下的可管理技能；`system` / `admin` 来源只读。
- 删除使用 VS Code 的回收站能力（`workspace.fs.delete(..., { useTrash: true })`），失败时给出可操作的提示。
- 删除后刷新列表并回到列表页。

### 3.7 状态、文案与可访问性

- 页面标题与入口文案按最终范围统一：若本轮不做远程市场，建议改为「技能管理」或在市场页明确「本地技能」。
- 列表行使用可聚焦的按钮/链接语义；开关保留 `role="switch"` 与 `aria-checked`。
- 统一空状态、错误态、加载态与成功提示的样式。
- 窄宽度下保证标题、描述与开关不重叠。

### 3.8 测试与验收

- 扩展侧测试：
  - 列表成功/失败、分条错误展示；
  - 启停失败回滚；
  - 导入同名覆盖/重命名/取消；
  - 删除权限保护（system/admin 不可删）；
  - 详情读取的路径安全。
- Webview 测试（沿用 `test/webview.test.js` 的 jsdom 方式）：
  - 搜索与筛选；
  - 点击行进入详情、返回；
  - 开关乐观更新与失败恢复；
  - 加载/错误/空状态。
- 验证命令：`npm run check`、`npm test`、`npm run build`。

## 4. 阶段二：远程技能市场（需确认后端条件）

### 4.1 能力范围

- 市场页与已安装页分离：市场浏览、分类/搜索、详情、安装。
- 已安装列表支持检查更新、更新、卸载。
- 安装来源与版本可追踪；市场安装的技能才允许市场侧更新/卸载。
- 组织内发布/审核可作为后续阶段。

### 4.2 目录接口草案

建议由 DiCode 服务端提供，或先托管静态目录 JSON：

```http
GET {serverUrl}/skill-market/api/v1/skills?query=&category=&page=&pageSize=
```

```json
{
  "data": {
    "items": [
      {
        "id": "example-skill",
        "name": "示例技能",
        "description": "一句话描述",
        "version": "1.0.0",
        "author": "team",
        "categories": ["frontend"],
        "tags": ["react"],
        "updatedAt": "2026-11-18T00:00:00Z",
        "downloadUrl": "https://.../example-skill-1.0.0.zip",
        "sha256": "...",
        "size": 12345
      }
    ],
    "total": 1
  }
}
```

- 详情接口返回 `SKILL.md` 或 README 内容、版本历史、文件清单。
- 鉴权复用现有 access token；401 时走现有刷新逻辑。
- 若服务端暂不可用，可先支持 `dicodeCodex.skillMarketUrl` 指向静态目录 JSON，扩展侧完成浏览与安装，服务端后续替换。

### 4.3 安装包与安全

- 安装包使用 zip，下载到临时目录，校验 `sha256` 与体积上限。
- 解压时拒绝绝对路径、`..`、符号链接和超限文件，原子替换目标目录，失败回滚。
- 安装前展示来源、版本、文件清单与安全提示（技能可包含脚本与指令）。
- 安装记录写入可追踪的元数据（例如 `<workspace>/.dicode/skills.json` 或技能目录内清单），记录来源、版本、安装时间。
- 更新采用「备份 → 安装 → 校验 → 切换」流程，失败恢复旧版本。

### 4.4 UI

- 市场/已安装切换；分类标签、搜索、排序。
- 市场卡片展示名称、描述、作者、版本、安装状态。
- 详情页提供安装/更新/卸载按钮与进度反馈。
- 安装成功后可跳转已安装列表并提示重启/刷新 Codex 技能。

## 5. 阶段三（可选）

- 组织内发布、审核与可见范围。
- 收藏、推荐、使用统计。
- 自动检查更新与批量更新。
- 技能版本回滚与变更日志。
- 多语言文案。

## 7. 验收标准

### 阶段一

- [ ] 技能页可手动刷新，加载/失败/空状态清晰，可重试。
- [ ] 列表支持来源筛选/分组与完整搜索。
- [ ] 点击技能可查看详情与 `SKILL.md` 内容。
- [ ] 导入支持同名处理，失败有明确提示且不破坏已有技能。
- [ ] 启停为乐观更新，失败自动回滚并提示原因。
- [ ] 可删除工作区/用户范围内的技能；系统/组织技能不可删。
- [ ] 详情读取和删除有路径安全校验。
- [ ] `npm run check`、`npm test`、`npm run build` 全部通过。

### 阶段二

- [ ] 市场页可浏览、搜索、分类与查看详情。
- [ ] 安装前校验来源、版本、哈希与包内容安全。
- [ ] 安装/更新/卸载可回滚，失败不破坏现有技能。
- [ ] 已安装列表可检查更新并显示当前版本。
- [ ] 市场接口或静态目录地址可配置。

## 8. 待确认事项

1. **本轮范围**：只做阶段一（推荐），还是阶段一 + 静态目录版市场？
2. **市场后端**：DiCode 服务端是否已有技能目录/下载接口？若没有，是否接受先用可配置的静态目录 JSON？
3. **删除权限**：是否允许删除用户级技能，还是只允许工作区级？
4. **导入格式**：是否需要支持 zip 或单个 `SKILL.md`？
5. **未登录体验**：技能页是否必须登录后才能使用？是否需要在未登录时只展示本地技能？
6. **页面命名**：继续叫「Skill 市场」，还是本轮先改为「技能管理」？
7. **安全提示**：详情页是否默认展示技能内所有文件内容，还是只展示 `SKILL.md` 与文件清单？
8. **发布节奏**：本轮完成后是否递增扩展版本并打 VSIX？

## 9. 建议执行顺序

1. 确认第 8 节的范围与后端条件。
2. 阶段一按「数据模型 → 列表/状态 → 详情 → 导入/删除 → 启停可靠性 → 测试」推进。
3. 阶段一验收通过后再启动阶段二，市场后端与安装包校验并行设计。
