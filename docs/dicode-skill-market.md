## 1. 范围与环境约束

### 1.1 实施范围

界面分两个页签，职责不重叠：

- **【全部】远程市场**：入口与布局、搜索与筛选、卡片字段、详情、缺省与异常状态。
- **【已安装】本地技能管理**：本机索引与登记合并、来源区分、导入（文件夹与 zip）、详情、删除、启停、未登录可用。
- **安装**：五态状态机、安装链路、去重、后台继续、失败与重试、索引刷新、版本更新（详情页发起，复用覆盖管道），以及安装与删除在两页签间的同步。
- **持久化与恢复**：按工作区的安装登记、按机器保存的安装任务日志、离线可用、安装事件与重连。

范围分三层，避免把「PRD 要求」和「现状补齐」混为一谈，详见 2.4：PRD V4.0.1 条款全部纳入不裁剪；本地导入/删除/启停属现状能力补齐（PRD 未要求，但现有功能不能回退）；zip 导入与手工放置项管理属用户指定新增。

### 1.2 环境约束与应对

| 约束 | 影响 | 应对 |
| --- | --- | --- |
| 市场接口在内网，当前不可达 | 无法联调真实目录与下载 | 阶段 0–3 用桩数据与本地桩包打通全链路，数据源单独隔离，阶段 4 只替换实现 |
| 内网账户与真实技能包不可得 | 无法验证真实兼容性与组织策略 | 兼容状态、组织限制、来源校验在桩数据中构造用例，逻辑先落地，阶段 4 校准 |
| Codex CLI 行为未验证 | 未登录能否调用技能 RPC 未知 | 阶段 1 首项即做验证，并备好退化方案 |
| 现有导航是顶栏图标，PRD 要求左上导航四项 | 不改则【已安装】页签没有入口，阶段 1 无法验收 | 导航改造作为**阶段 1 前置任务**由本模块完成（见 3.1），不依赖其他需求排期 |
| 本机未验证 VSIX 打包与分发 | 阶段 3 收尾的内测包可能受阻 | `@vscode/vsce` 已在 devDependencies；阶段 3 开始前先跑一次 `npx vsce package --no-dependencies` 验证环境，不可用则内测顺延 |
| 终端组件不在本仓库 | PRD 发布验收含「CLI 侧 Skill 安装」，本仓库无法覆盖 | 不在本模块职责范围，由终端团队负责（见 1.3） |

### 1.3 其他模块边界与外部风险

- **终端/CLI 的 Skill 安装**：不在本模块职责范围。本模块只负责 VS Code 扩展侧（`apps/dicode-vscode`），CLI 侧安装由终端团队自行负责，本文档不排期、不验收、不输出复用契约，也不与终端团队做接口对齐。
- 消息提醒中的安装失败：需求的消息提醒只覆盖任务待决策与任务动态，本模块不扩展提醒。
- 跨会话记忆、待决策强提醒：属 V4.0.2，由对应模块负责。
- 导航栏改造：只做「左上四项导航 + 左下用户中心/设置」的入口搬迁，不改其余页面内容，不改最小化/最大化开关（后者属 IDE 布局需求）。

## 2. 分步实施路线

### 2.1 划分原则

按环境依赖切分：先做不依赖外部条件的部分，再做依赖本地可验证条件的部分，最后做必须依赖内网的接入。每个阶段可单独交付、单独验收，中断后可从下一阶段继续。

### 2.2 阶段总览

| 阶段 | 主题 | 外部依赖 | 主要产出 |
| --- | --- | --- | --- |
| 0 | 数据底座 | 无 | 模型、状态推导、登记读写、任务日志与目录锁 |
| 1 | 导航与【已安装】页签 | Codex CLI | 左上导航改造、两页签容器、索引与登记合并、导入（文件夹 + zip）、详情、删除、启停、技能 client |
| 2 | 【全部】市场浏览 | 无（桩数据） | 列表、详情、布局、缓存 |
| 3 | 安装链路 | 无（本地桩包） | 安装管道、去重、回滚、中断恢复、索引刷新、详情页更新入口、内测包 |
| 4 | 真实接口接入 | 内网接口 | 契约校准、联调、错误码映射 |
| 5 | 文档与收尾 | 阶段 4 之后 | 使用文档、最终回归 |

阶段 0–3 完全可在本地完成（详情页更新入口在阶段 3 一并交付，复用同一条覆盖管道，不依赖内网）。阶段 4 是唯一硬依赖内网的阶段；阶段 5 只剩使用文档与回归。

### 2.3 各阶段任务

**阶段 0：数据底座**

- 产出：`skillsModel.js`（类型、`compareVersion`、状态推导、去重键、目录名校验）、`skillsRegistry.js`（登记读写、原子写、短锁、损坏恢复）、`skillsJobs.js`（安装任务日志、目录锁与心跳、失效清理）。
- 关键点：登记是「已安装」与离线可用的唯一真相来源，路径与格式在本阶段定死；任务日志是重启后判定 `INTERRUPTED` 的唯一来源，存 `context.globalStorageUri` 下，按工作区一份。
- 同时把 `npm run check` 从「3 个固定文件」改为覆盖全部 `.js`（12.3），否则本阶段及后续新增模块都不在语法检查范围内。
- 验证：`skills-registry.test.js` 覆盖原子写、并发锁、损坏恢复、跨窗口读一致性；`skills-jobs.test.js` 覆盖任务日志写入与重放、锁心跳超时、过期锁清理。

**阶段 1：导航与【已安装】页签**

- 前置任务（新增，先于页签开发）：把当前顶栏右侧四个图标（`webview/app.tsx` 的 `top-actions`）改为 PRD 要求的左上导航四项【对话、Skill 市场、历史对话、消息提醒】，左下固定【用户中心、设置】；进入市场子页后返回对话保留输入中草稿。产出 `webview/NavRail.tsx`，导航与页签切换不重建会话状态。
- 前置验证：空 token 启动 app-server 后 `skills/list`、`skills/config/write` 是否可用。可用则走独立技能 client；不可用则退化为自行扫描技能目录 + 写用户级配置，并在本文档记录差异。
- 产出：`ensureSkillClient()`、`skillArchive.js`（zip 读取与安全解压）、`installedView.js`（索引与登记按 `dir` 合并、三类来源判定）、导入（文件夹 + zip，重名时覆盖（仅限本地导入项）、重命名、取消）、`getSkillDetail` / `deleteSkill` / `reimportSkill` / `unregisterSkill` / `openSkillFile` / `revealSkill`、启停乐观更新与回滚、`webview/Installed.tsx`、两页签容器。
- 关键点：本页签不调用任何远程接口；导入成功后写 `source: import` 登记；手工放置项不写登记；保留现有「已启用」筛选，不因改版丢掉既有能力。
- 验证：未登录状态下可列举、查看详情、导入、删除、启停（启停依赖 Codex CLI，缺失时按 9.1 提示且不影响其余操作）；三类来源都能显示；`system` / `admin` 来源不可删。

**阶段 2：【全部】市场浏览**

- 产出：`marketStub.js`（目录与详情数据、可指定状态用于渲染五态、可构造四类错误）、`skillMarket.js`（数据源抽象，桩与真实接口同一出口）、`webview/skills.ts`、`webview/Market.tsx`、页签切换与选中态、列表与详情样式。
- 关键点：服务端搜索与筛选、卡片字段（版本、简介、兼容状态齐全）、「已安装」标记只认 market 登记、骨架、缓存过期标注、最大化态列表与详情并排。
- 桩的职责边界：阶段 2 的桩只产出「目录数据 + 状态字段」，用于渲染五态按钮；**不模拟安装过程**（点击安装、延迟返回、首次必失败等行为统一由阶段 3 的真实管道 + 本地桩包承担），避免阶段 2、3 各有一套假安装逻辑。
- 验证：jsdom 覆盖搜索、页签切换与五态按钮渲染；手工走查 VS Code 深/浅与 JetBrains 深/浅四套主题。
- 风险：设计稿缺版本、简介、兼容状态与详情页，字段先按需求实现并留空态兜底。

**阶段 3：安装链路**

- 产出：`skillInstaller.js`（下载、摘要校验、解压、登记、覆盖回滚）、安装任务表与事件（含 `seq`）、事件幂等、中断恢复、索引刷新、详情页更新入口（复用 8.3 覆盖管道）。
- 关键点：去重键 `(workspaceId, skillId, version)`；覆盖用 `.new` / `.bak` 目录切换；失败清理临时文件且旧版本可用；重连先快照后增量；任务日志落盘后才能判定 `INTERRUPTED`。
- 验证：连续点击只产生一个 `jobId`；摘要不符、来源校验失败、不兼容、组织限制四类均不写登记（其中摘要不符进可重试）；覆盖失败回滚；扩展重启后中间态转 `INTERRUPTED`；第二个窗口在同一工作区发起同名安装被拒绝或接入同一任务，而不是并发写入；目录项存在更高版本时详情页可发起更新，成功后登记版本递增、旧版本在失败时仍可用。
- 收尾：递增扩展版本并打一版内测 VSIX，桩数据模式下走通真实安装流程，先收一轮问题再进阶段 4。

**阶段 4：真实接口接入**

- 产出：`skillMarket.js` 真实实现、鉴权、分页、错误码映射、缓存 TTL 与淘汰、真实下载与摘要来源。
- 关键点：契约以服务端实际响应校准，字段缺失在适配层补齐，不把服务端差异泄漏到 UI。
- 验证：逐条核对 12.2 验收表；目录失败、超时、离线三条路径均能回到可用状态。

**阶段 5：文档与收尾**

- 使用文档（市场与本地技能操作说明）、最终全量回归。
- 进入条件：阶段 0–4 全部验收通过。技能更新入口已在阶段 3 交付，本阶段不重复。

## 3. 产品形态

### 3.1 入口与布局

- 左上导航第 2 项【Skill 市场】进入，回到对话后保留输入中草稿。导航形态由阶段 1 前置任务改造而来（1.2、2.3），本模块负责落地，不等待其他需求排期。
- 页内两个页签：【全部】与【已安装】。两者是两套独立数据源，不是同一份列表的过滤条件（PRD「已安装筛选以当前工作区登记记录为准」支持这一取舍，措辞差异登记在 14 节）。
- 默认页签：已登录进【全部】，未登录进【已安装】，保证未登录也能管理本地技能。
- 窄面板：市场占据插件内容区，列表与详情为前后两级。
- 最大化态：列表与详情并排（左侧列表、右侧详情）。市场子页最大化时**以列表 + 详情并排为准**，不沿用对话页「左侧常驻历史列表」的布局；切回对话页时恢复历史列。
- 切换导航项或页签不重建市场状态，已发起的安装任务不受影响。

### 3.2 两个页签

| | 【全部】 | 【已安装】 |
| --- | --- | --- |
| 定位 | 远程技能市场，检索与安装 | 本地技能管理 |
| 数据来源 | 远程目录，分页 | 本机技能索引 + 工作区登记 |
| 外部依赖 | 登录 + 内网接口 | 无（不联网、不要求登录） |
| 搜索与筛选 | 下发服务端（`q`、`filter`） | 本地内存过滤，不发任何请求 |
| 主要操作 | 安装、重试、查看详情 | 导入（文件夹 / zip）、启停、删除、查看详情 |

两套数据源不要混用：【已安装】不得从远程分页结果里过滤得出，也不得把「已加载到内存的市场目录」当作它的数据源——否则已装技能落在第 3 页就查不到，目录外的本地技能（导入、手工放置）更是永远看不到；【全部】不得用本地索引拼装，否则看不到未安装的技能。

**【全部】**

- 卡片展示：名称、发布者、版本、简介、兼容状态、安装操作。
- 排序按发布者 + 名称稳定排序，避免刷新跳动；已安装项不提前置顶。
- 「已安装」判定只看登记中 `source: market` 且 `skillId` 命中的记录。本地导入或手工放置的同名技能不算已安装——它们不是市场分发的同一个东西。
- 同名本地占用：市场条目的目标目录已被本地导入或手工放置的目录占用时，卡片在安装操作旁附注「本地已有同名技能」，避免用户点了【安装】必然收到 `DIR_CONFLICT`（处理规则见 8.3）。

**【已安装】**

- **与市场完全独立**：数据只来自本机磁盘与工作区登记。market 模块、远程目录接口、登录态、目录缓存都不参与；市场接口挂了、未登录、甚至没有配置市场，本页签照常工作。它的语义是「这台机器这个工作区里真实存在、可被 Agent 发现的技能」，不是「市场目录里我点过安装的那几条」。
- 数据来源是**本机技能索引 ∪ 工作区登记**，两侧只提供自己有的字段：索引提供 `path`、`scope`、`enabled` 与存在性；登记提供 `skillId`、`source`、`version`、`publisher`、`summary`、`tags`。合并后按 9 节判定三类来源，任一侧都不是「唯一的列表主体」。
  - 索引优先取 Codex CLI 的 `skills/list`；CLI 不可用时退化为扫描 `.agents/skills/`（见 9.1），此时 `scope` 按目录位置推断、`enabled` 显示为未知，不阻塞列表。
- 三条来源都要能显示：市场安装、本地导入、手工放置。
- 元数据**不向远程请求**：登记项取登记，手工放置项取 `SKILL.md` frontmatter 的 `name` 与 `description`，缺失字段显示空态。未登录、远程不可达都不影响本页签。
- 每项展示来源标签，并区分四种异常：登记有但目录已不存在（`missing`）、目录存在但登记无记录（`external`）、已安装但 Agent 索引未刷新（`indexStale`）、安装后目录内容与登记摘要不一致（`altered`，仅附注「本地已修改」，不改变已安装状态）。
- 搜索匹配名称、简介、标签，本地导入与手工放置项额外匹配路径。
- 保留「已启用」筛选（现有 `SkillList` 具备，改版后继续提供）。
- 安装成功、导入成功、删除成功后本页签立即反映，不依赖手动刷新。

### 3.3 详情

- 市场侧字段：用途、来源、版本、声明能力、示例。
- 【全部】的详情由远程接口返回，不下载包即可查看。
- 【已安装】的详情直接读本地：元数据取登记，正文读 `SKILL.md` 全文，附文件列表与所在目录。
- 本地 `SKILL.md` 只有 `name` / `description` 两个结构化字段，**声明能力与示例无法从本地解析**：这两项在【已安装】详情中显示空态并注明「由市场提供」，不做猜测性解析；市场项沿用市场详情返回的 `capabilities` / `examples`。
- 详情内的安装/重试操作复用列表的状态机。

### 3.4 缺省与异常状态

| 场景 | 表现 |
| --- | --- |
| 初次加载 | 骨架屏或加载提示，不显示空态 |
| 目录请求失败 | 有缓存则展示缓存并标注已过期 + 重试；无缓存则错误态 + 重试，并提供「切到【已安装】」的动作（本地管理不被市场故障连坐） |
| 未登录 | 【全部】显示登录引导，不是错误态；【已安装】正常可用 |
| 已安装列表 | 完全离线可读，来自本地索引与登记 |
| 登记有、目录无 | 该条标为目录缺失，提供「重新导入」与「从登记移除」 |
| 目录有、登记无 | 该条标为手工放置，可启停与查看详情，删除需二次确认 |
| 市场条目目标目录被本地技能占用 | 卡片附注「本地已有同名技能」，安装被阻断并给出处理建议（8.3） |
| 搜索无结果 | 空态提示，保留当前关键词与页签 |
| 单条安装失败 | 该条转【重试】并保留失败原因，不影响其他条目 |

### 4.2 与目标的差距

1. 没有远程目录：无接口、无分页、无版本与兼容状态。
2. 没有安装链路：只能从本地导入。
3. 没有登记记录：「已安装」靠实时扫描，离线不可用，也无法区分来源。
4. 没有详情页：看不到 `SKILL.md`、来源、文件列表。
5. 没有删除、没有重新导入、没有移出登记：导入后只能启停，目录需手动清理。
6. 未登录不可用：`listSkills` / `setSkillEnabled` 经 `ensureClient()` → `accessToken()`，未登录直接抛错；`importSkill` 虽不依赖登录，但导入后刷新被拒，表现为「文件已复制但页面报错」。
7. 状态反馈不完整：无真正加载态，启停失败走通用 `error` 且技能页不展示，分条 `errors` 被压成一句话。
8. 启停不可靠：非乐观更新、无逐项 pending、无失败回滚。
9. 数据模型未定义：前端以 `any` 处理，以 `path` 作 key。
10. 导入能力有限：仅支持文件夹，无 zip、无覆盖与重命名。
11. 入口形态不符：PRD 要求左上导航四项，现状是顶栏右侧图标。

### 5.2 安装登记（按工作区持久化）

登记是【已安装】页签的主数据源，存于 `<workspace>/.agents/skills.registry.json`。市场安装与本地导入都要写登记，区别仅在 `source`；手工放进 `.agents/skills/` 的技能不写登记，由索引侧识别为 `external`。

```js
/** @typedef {Object} InstallRecord
 * @property {string} skillId        market 安装取目录项 id；本地导入取 SKILL.md 的 name
 * @property {string} name           展示名，取自 SKILL.md
 * @property {string} version        market 取目录项版本；本地导入为 '0.0.0-local'
 * @property {string|null} digest    market：服务端包摘要（zip），升级前校验用；本地导入为 null
 * @property {string} dirDigest      安装完成时目录内容的 sha256，用于检测外部改动（altered）
 * @property {string} dir            相对工作区的安装目录：.agents/skills/<来源目录名>（见 5.5）
 * @property {'market'|'import'} source
 * @property {string} origin         市场包内根目录名 / 导入源文件夹名，供排查
 * @property {number} installedAt
 * @property {string} [publisher]    market 安装时随目录项落库，供离线渲染
 * @property {string} [summary]      同上
 * @property {string[]} [tags]       同上
 * @property {boolean} [indexStale]  登记成功但 Agent 索引未刷新
 */
```

- 两种摘要不能混用：`digest` 是**包**摘要，本身不等于**目录**摘要；`dirDigest` 才是目录内容摘要。已安装判定不依赖摘要比对（见 5.4），否则会出现「包摘要永远不等于目录摘要、已安装永远不成立」的死结。
- `dirDigest` 只在安装/导入完成时计算一次并落库，列表渲染**不重算**——否则每次刷新都要对每个已安装项做全目录 sha256，技能多时明显卡顿。仅在打开详情或用户主动校验时比对，用于标记 `altered`。
- 登记自带足以离线渲染列表与详情的字段（`name`、`publisher`、`version`、`summary`、`tags`）。【已安装】页签不回远程补字段，缺什么显示空态。
- 手工放置项不自动写登记：它们多为团队共享文件或用户自行拷贝，写登记会与 git 同步互相打架。需要转为受管项时走「重新导入」。

写入要求：先写 `.registry.json.tmp` 再 `rename`；多窗口用 `.registry.json.lock` 短锁；解析失败视为空登记并把损坏文件留为 `.bak`，不阻塞页面。

该文件是机器生成的工作区状态，**不入版本控制**。扩展不静默修改用户的 `.gitignore`：首次写登记时检测工作区 `.gitignore` 是否已忽略该路径，未忽略则提示一次并提供「加入 .gitignore」动作（写入工作区根 `.gitignore`，需用户确认）。团队想共享「该项目该装哪些技能」时，另出一份只含 `skillId` 与版本的手写推荐清单，不与登记文件混用。

### 5.3 安装任务

```js
/** @typedef {Object} InstallJob
 * @property {string} jobId
 * @property {string} workspaceId    工作区标识（工作区路径的稳定散列），事件与去重都按它隔离
 * @property {string} skillId
 * @property {string} version
 * @property {string} digest
 * @property {'queued'|'downloading'|'verifying'|'extracting'|'registering'|'done'|'failed'} state
 * @property {number} seq            本任务的事件序号，从 0 单调递增
 * @property {number} [progress]     0-100，下载阶段有效
 * @property {string} [errorCode]
 * @property {string} [errorMessage]
 * @property {boolean} retryable
 * @property {number} startedAt
 * @property {number} [finishedAt]
 */
```

持久化：任务表写 `<globalStorageUri>/skill-jobs/<workspaceKey>.json`（`workspaceKey` 取工作区路径的短散列），原子写。任务日志是机器本地状态、不属于工作区内容，因此不写进 `.agents/`，也不随仓库同步。扩展启动时读取该文件，把所有非终态任务置为 `failed` + `INTERRUPTED`（可重试）。

### 5.4 安装状态机

```
ready ──install──▶ installing ──ok──▶ installed
                      │
                      ├──retryable fail──▶ failed ──retry──▶ installing
                      └──non-retryable──▶ blocked（保留原因，不可重试）
```

- `installing` 细分管道阶段（downloading → verifying → extracting → registering），UI 统一显示【安装中…】。
- `installed` 判定：登记中存在该 `skillId` 且 `source: market`，且 `<dir>/SKILL.md` 存在。**不比对 `digest`**；`dirDigest` 不一致只标 `altered`（本地已修改），不改变已安装状态。`source: import` 的登记不参与本状态判定。
- `failed` 转 `retry` 的条件是 `retryable: true`，取值见 7.1；不可重试的错误直接进 `blocked` 并展示原因，不提供重试按钮。
- `blocked` 是终态：再次点击安装会生成新 `jobId`（去重只看在跑任务），不复用旧 ID。

**状态 → 按钮文案（PRD 五态 + 任务级阻断的唯一口径）**

| 目录级 / 任务级 | 按钮 | 可点击 | 附注 |
| --- | --- | --- | --- |
| 无登记、`compat: compatible` | 【安装】 | 是 | 目标目录被本地同名技能占用时附注「本地已有同名技能」 |
| 任务在跑（含 `queued`） | 【安装中…】 | 否 | 显示进度或阶段文案 |
| 已安装 | 【已安装】 | 否 | 登记版本落后于目录项时附注「有 vX 可用」，更新入口在详情页（阶段 3） |
| 任务失败且可重试 | 【重试】 | 是 | 保留失败原因 |
| `compat: incompatible` | 【不兼容】 | 否 | 显示最低客户端版本 |
| `compat: restricted` | 【已限制】 | 否 | 显示组织策略说明 |
| 安装中被阻断（来源校验/目录冲突/包非法） | 【无法安装】 | 否 | 显示具体原因；**不复用**【不兼容】/【已限制】，避免文案与原因错位 |

PRD 五态中没有「可更新」态，因此列表按钮不新增第 6 种状态；版本更新入口放在详情页，随安装链路在阶段 3 交付（复用同一条覆盖管道，不另立管道），登记在 14 节。

### 5.5 目录命名与校验

统一规则：**安装目录名取「来源目录名」**，与现有导入行为一致，且不改动存量目录。

- 市场安装：取 zip 包内技能根目录名（单层根目录自动剥离后剩下的那一层，见 8.1）。
- 本地导入：取源文件夹名（与现状 `importLocalSkill` 一致）。
- 两者都不加发布者前缀、不加版本后缀、不加随机串；同名冲突按 8.3 处理，不自动改名。

安全校验（三种路径共用，`skillsModel.normalizeDirName`）：

- 必须是非空单层名称：拒绝 `.`、`..`、含 `/` 或 `\`、含控制字符、以 `.` 开头的隐藏名。
- 拒绝 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1..9`、`LPT1..9`）与结尾的 `.`、空格。
- 不做大小写折叠、不做非法字符替换：名字不合规就拒绝并报 `ARCHIVE_INVALID`（导入场景提示用户改文件夹名）。静默改名会让用户找不到自己的技能，也违背「保持原名」的既有决策。
- 长度上限 64 字符。

存量兼容：既有导入目录名本来就是源文件夹名，与新规则一致，无需迁移。若历史上手工改过目录名，登记里的 `dir` 仍是唯一依据，按 `dir` 识别，不按名称反推。

## 6. 消息协议

扩展侧统一在 `extension.js` 的消息分支处理，实现放独立模块。旧消息保持字段兼容（新增字段可选、缺省有默认值），不删不改语义。

| 方向 | 消息 | 参数 / 返回 | 说明 |
| --- | --- | --- | --- |
| Webview → 扩展 | `marketList` | `{ query?, filter?, cursor? }` | 拉远程目录，服务端搜索与筛选，分页返回；仅【全部】页签使用 |
| | `marketDetail` | `{ skillId, version? }` | 请求远程详情 |
| | `marketInstall` | `{ skillId, version, digest }` | 提交安装，返回 `{ jobId }`；版本更新复用本条消息，传目录中的新 `version` 与对应 `digest`，不另立消息 |
| | `marketRetry` | `{ jobId }` | 重试可重试的失败任务，返回新 `{ jobId }`（不复用旧 ID） |
| | `getInstallJobs` | 无 | 主动拉取当前工作区在跑任务快照（含其他窗口发起的），webview 重开或切回市场时先调用一次，之后靠 `installEvent` 增量 |
| | `installedList` | 无 | 【已安装】页签全量：本机索引 ∪ 工作区登记，纯本地，不请求远程 |
| | `listSkills` | 无 | 取 Codex 技能索引 |
| | `getSkillDetail` | `{ path }` | 本地详情：元数据 + `SKILL.md` + 文件列表 |
| | `importSkill` | `{ mode? }`，`folder` 或 `zip` | 本地导入；`mode` 缺省按 `folder`，兼容旧 webview |
| | `reimportSkill` | `{ path }` | 重新导入缺失目录项；继承原登记的 `source` 与 `skillId` |
| | `unregisterSkill` | `{ path }` | 仅移出登记、不动磁盘文件（目录已不存在时的清理入口） |
| | `setSkillEnabled` | `{ path, enabled }` | 启停 |
| | `deleteSkill` | `{ path }` | 删除目录 + 清登记，仅可管理来源 |
| | `openSkillFile` / `revealSkill` | `{ path }` | 打开文件 / 资源管理器定位 |
| 扩展 → Webview | `marketCatalog` | `{ items, nextCursor, cachedAt, stale, query, filter }` | `items` 为**本页**条目，前端按 `nextCursor` 追加；`stale` 表示来自缓存；回带 `query`/`filter` 供前端丢弃过期响应 |
| | `marketDetailResult` | `{ skillId, version, skill, content }` | 远程详情结果（与请求消息区分命名，避免双向同名） |
| | `marketError` | `{ code, message, retryable, scope: 'catalog'\|'detail' }` | 目录/详情失败 |
| | `installJobs` | `{ jobs }` | 全量快照，重连先收快照再收增量 |
| | `installEvent` | `{ seq, workspaceId, jobId, skillId, version, digest, state, errorCode?, retryable?, progress? }` | 与需求的事件字段一致，`retryable` 由错误码推导，`seq` 为任务内单调递增序号 |
| | `installedSkills` | `{ items, reason: 'install'\|'import'\|'delete'\|'unregister'\|'toggle' }` | 【已安装】页签变更推送；`toggle` 只更新该项，其余 4 种整体替换 |
| | `skills` / `skillsDetail` / `skillsError` / `skillsNotice` | 沿用 | 本地技能 |

两个页签各自独立请求：`marketList` 只在【全部】签发，`installedList` 只在【已安装】页签发。安装成功后的 `installedSkills` 推送两页签都接收，前者据此把卡片转【已安装】，后者据此插入新项，避免两处各自轮询。

重开市场或 webview 重载时，先 `getInstallJobs` 取一次快照把在跑任务画出来，再接收 `installEvent` 增量；不能只依赖推送，否则断开期间的事件会永久丢失，按钮停在【安装】而实际已在安装。

事件合并：`installEvent` 按 `jobId` + `seq` 幂等，且只接受 `seq` 严格递增的事件——**不能用 `(jobId, state)` 作幂等键**，否则同一 `downloading` 状态下的多次进度事件会被当成重复丢弃，进度条只会动一次。已 `done` / `blocked` 的 `jobId` 不再接受后续事件。

## 7. 远程接口契约

接口在内网、当前不可达，本仓库先定契约，阶段 4 以服务端实际响应校准。鉴权复用现有 OIDC token，未登录不请求远程。

| 方法 | 路径 | 参数 | 返回要点 |
| --- | --- | --- | --- |
| GET | `/skill-market/api/v1/skills` | `q`、`filter`、`cursor`、`limit` | `{ items: MarketSkill[], nextCursor }` |
| GET | `/skill-market/api/v1/skills/{id}` | `version?` | `MarketSkill` + `usage`、`source`、`capabilities[]`、`examples[]`、`readme` |
| GET | `/skill-market/api/v1/skills/{id}/versions/{version}/download` | — | zip 流，响应头带 `digest` 与 `content-length` |

约束：

- 搜索与筛选由服务端执行：`q` 匹配名称、简介、标签；`filter` 为服务端筛选枚举，当前只有 `all`，后续分类、来源、发布者等条件都在此扩展，客户端不为其新增消息。
- 列表分页，客户端不一次拉全量；翻页时保留当前 `q` 与 `filter`。
- 【已安装】页签不请求任何远程接口，元数据只读登记。远程不可达、未登录都不影响它，因此接口侧不为它设计批量补齐能力。
- `digest` 以服务端返回为准，客户端下载后重算比对，不一致即失败。
- 目录缓存写 `context.globalStorageUri` 下 `market-cache.json`，全局一份、跨工作区共用，TTL 10 分钟；过期先展示缓存再后台刷新。
- 缓存按 `q` + `filter` 分组存储，切换筛选条件不互相覆盖。分组上限 20 个、文件总量上限 2 MB，超出按最近使用时间淘汰最旧分组，避免自由文本检索让缓存无限增长。

### 7.1 错误码

| errorCode | 触发 | 可重试 |
| --- | --- | --- |
| `NETWORK` | 请求超时、连接失败 | 是 |
| `UNAUTHORIZED` | token 失效 | 是（重新登录后；重试前先确认登录态，仍失效则转登录引导） |
| `NOT_FOUND` | 技能或版本不存在 | 否 |
| `INCOMPATIBLE_CLIENT` | 客户端版本低于 `minClientVersion` | 否 |
| `ORG_RESTRICTED` | 组织策略限制 | 否 |
| `SOURCE_VERIFY_FAILED` | 来源/签名校验失败 | 否 |
| `ARCHIVE_INVALID` | 包结构非法：缺 `SKILL.md`、含符号链接、绝对路径或 `..`、目录名不合规 | 否 |
| `ARCHIVE_TOO_LARGE` | 解压后超过总量/文件数/单文件限额 | 否 |
| `DIGEST_MISMATCH` | 摘要比对不一致 | 是 |
| `DISK_FULL` | 磁盘空间不足 | 是（用户清理空间后可原地重试） |
| `VERSION_CONFLICT` | 登记文件并发写导致版本冲突 | 是 |
| `LOCK_TIMEOUT` | 目标目录被其他窗口/任务长期占用，心跳失效前无法获取 | 是 |
| `DIR_CONFLICT` | 目标目录已被其他技能的登记或手工文件占用 | 否 |
| `INTERRUPTED` | 扩展重启导致任务中断 | 是 |

`LOCK_TIMEOUT` 与 `VERSION_CONFLICT` 不复用同一码：前者是锁等待超时，后者是登记内容冲突，排查路径不同。

### 7.2 桩数据

- `apps/dicode-vscode/marketStub.js` 内置一份目录与详情，覆盖五态所需字段：可安装、安装中（仅渲染用，状态由外部指定）、已安装、可重试、不可安装（一条 `incompatible`、一条 `restricted`）。
- 桩只负责「数据与状态字段」，**不模拟安装动作**；真实的下载、解压、失败与重试由阶段 3 的管道 + 本地桩包驱动，避免阶段 2、3 各有一套假安装逻辑。
- 启用条件：配置项 `dicodeCodex.skillMarketStub` 为 `true`；默认关闭，避免误连。配置项在 `package.json` 的 `contributes.configuration` 中声明。
- 桩数据只在扩展侧生效，webview 不感知来源，阶段 4 只替换 `skillMarket.js` 的数据源实现。
- 桩包是固定结构 zip（单层根目录 + `SKILL.md`），供阶段 3 打通下载、解压与登记；另备一个「缺 `SKILL.md`」和一个「超限」包用于异常用例。

## 8. 安装链路

### 8.1 管道

1. 校验目录项：`compat` 必须为 `compatible`；目标目录若已被**其他 `skillId` 或未登记目录**占用，先按 8.3 判冲突，避免下载完才失败（同一 `skillId` 的既有目录属升级场景，不算冲突）。
2. 去重：按 `(workspaceId, skillId, version)` 查在跑任务（含其他窗口写入的任务日志），命中则复用原 `jobId`。
3. 下载：写 `context.globalStorageUri/downloads/<jobId>.zip`，报进度，每阶段至少发一次带 `seq` 的事件。
4. 校验：重算 sha256 与 `digest` 比对。
5. 解压：复用 `skillArchive.js` 的安全解压规则（见 9.2），拒绝绝对路径、`..`、符号链接、加密条目、超限包。
6. 定位技能根：单层根目录自动剥离；多层或直接放根部的，以 `SKILL.md` 所在目录为技能根；目录名按 5.5 校验。
7. 内容校验：`SKILL.md` frontmatter 必须含 `name`、`description`，且 `name` 与目录项 `name` 一致（身份校验；目录名不再由 `name` 决定，见 5.5），不一致按 `SOURCE_VERIFY_FAILED` 拒绝。
8. 登记：写入 `<workspace>/.agents/skills/<来源目录名>`，成功后原子写登记。
9. 刷新：`skills/list` 带 `forceReload: true`，让 Agent 索引立即生效。
10. 清理：无论成败删除临时 zip 与临时解压目录。

临时目录必须建在目标同级（`<workspace>/.agents/skills/.tmp-<jobId>`）而不是 `globalStorageUri`：跨盘时 `rename` 会因 `EXDEV` 失败，同盘同目录才能保证原子切换，且失败清理不触碰已安装版本。

### 8.2 去重与并发

- 同一 `(workspaceId, skillId, version)` 只有一条 `InstallJob`，连续点击不产生第二条记录。去重依据是**任务日志文件**而非内存表，第二个窗口也能看到在跑任务。
- 目录写入前加锁：`<globalStorageUri>/skill-locks/<workspaceKey>/<dir>.lock`，内容为 `{ owner, pid, heartbeatAt }`，运行期每 5 秒心跳。
- 锁失效判定：`heartbeatAt` 超过 30 秒未更新视为持有者已死，清理后可获取；**未失效的锁不能强行抢占**，等待超时（默认 60 秒）报 `LOCK_TIMEOUT`（可重试）。不做「锁文件存在超过 N 秒就删」的时间判断。
- 不同技能可并行，并发安装上限 2；同一技能不同版本串行，避免互相覆盖。超过上限的请求进 `queued`。

### 8.3 覆盖与回滚

目录名取「来源目录名」，不加发布者前缀、不加版本后缀（5.5）。冲突按来源与 `skillId` 分四种处理：

- **升级（同一 `skillId`，版本不同）**：登记中该 `skillId` 已存在且 `dir` 相同，装到 `<dir>.new`，成功后 `<dir>` → `<dir>.bak`、`<dir>.new` → `<dir>`，再删 `.bak`。任一步失败：删 `.new`，`.bak` 还原，登记保持旧版本，原版本继续可用。目录名变化（市场侧改了包内根目录名）视为新目录安装，旧目录转 `missing` 并在详情提示，不自动删除。
- **目录冲突（不同 `skillId`，或登记无记录的目录）**：目标目录已存在时不覆盖、不改名，报 `DIR_CONFLICT`，并给用户两条明确路径——「删除本地目录后重新安装」（`DIR_CONFLICT` 不可重试，删除后点【安装】生成新 `jobId`）或「查看本地版本」。市场卡片提前附注（3.2），不让用户白点。
- **跨来源冲突（导入目标已被市场安装项占用）**：**直接阻断，不提供覆盖**。导入时检测到目标目录属于 `source: market` 的登记项，提示「该目录由市场管理，请先删除市场版本，或换个文件夹名导入」，不写登记、不动文件——避免一次导入把市场项悄悄变成本地项、在【全部】退回【安装】。反向（市场安装目标被本地导入项或手工目录占用）按上面的「目录冲突」处理（`DIR_CONFLICT`），先删除再安装。
- **并发**：同一目录的写入按 8.2 的锁串行，两个技能同时装到同名目录时只有一个成功，另一个报 `DIR_CONFLICT`。

### 8.4 后台继续与重连

- 安装跑在扩展宿主侧，webview 关闭或切走继续执行；重开市场先调 `getInstallJobs` 取快照（见 6 节），再接 `installEvent` 增量。
- 扩展重启：读取任务日志，把非终态任务标 `failed`（`INTERRUPTED`，可重试），并清理残留临时目录；已 `done` 以登记为准重建，不依赖任务日志。
- 多窗口同工作区：任务日志与锁都在 `globalStorageUri`，所有窗口共享。第二个窗口发起同名安装时命中在跑任务，接入同一条 `jobId` 订阅（只读），不重复执行；登记文件仍是最终真相来源，写入后其他窗口监听文件变化刷新。
- 跨机器/共享工作区（网络盘）：不支持并发安装，读到失效锁按 `LOCK_TIMEOUT` 处理，不强行写入。

### 8.5 索引刷新

安装成功必须让 Codex 重新扫描，否则装完不可用。失败时登记已写入但标 `indexStale: true`，页面提示「已安装，索引待刷新」并提供重试。「重试刷新索引」与安装重试是两条独立动作，不共用 `jobId`。

## 9. 【已安装】页签与本地能力

【已安装】页签就是本地技能管理，与 market 模块零耦合：不调用 market 的任何消息、不读目录缓存、不依赖登录与内网；市场整块不可用时它的行为完全不变。它把本机技能索引与工作区登记按 `dir` 取并集，三类来源都要展示：

| 来源 | 判定 | 可做的操作 |
| --- | --- | --- |
| 市场安装 | 登记有记录且 `source: market` | 启停、详情、删除、更新（阶段 3 起） |
| 本地导入 | 登记有记录且 `source: import` | 启停、详情、删除、重新导入 |
| 手工放置 | 索引有、登记无 | 启停、详情；删除需二次确认 |

- 两边各缺一边时不隐藏该项：登记有而索引无标 `missing`（目录被外部删除或切换分支导致），索引有而登记无标 `external`。
- 手工放置项不写登记，避免与 git 同步冲突；要转为受管项走「重新导入」。
- `reimportSkill` 继承原登记的 `skillId` 与 `source`：市场项重新导入后仍是 `market`，在【全部】仍显示【已安装】；若原目录已被替换为不同内容，按 `SOURCE_VERIFY_FAILED` 处理并保留旧登记。
- `reimportSkill` 与 `importSkill` 不是一回事，不要混用：前者只用于补齐缺失目录、**保持原身份**（市场项仍是 `market`）；后者是普通导入，目标若为市场安装项会被 8.3 直接阻断，不覆盖、不改 `source`。
- `unregisterSkill` 只删登记、不动文件：用于目录已被外部删除后的清理；执行后该项转为 `external`（目录仍在）或直接消失（目录已不在）。
- 按名称稳定排序，来源用标签展示，不做分组，避免安装后条目跳位。

### 9.1 未登录可用

1. 新增 `ensureSkillClient()`：不调用 `accessToken()`，启动独立 app-server 实例，仅用于 `skills/list` 与 `skills/config/write`；模型目录用 CLI 自带模型构造；实例随 webview 释放而 dispose，不常驻。
2. `importSkill`、`reimportSkill`、`unregisterSkill`、`getSkillDetail`、`deleteSkill`、`openSkillFile`、`revealSkill` 走纯文件系统，不依赖 client 与登录。
3. 退出登录只清理会话 client，不影响技能页。【已安装】页签在未登录时是默认页签，读取与操作全部可用。
4. Codex CLI 未安装时沿用 `ensureBinary()`，失败提示「设置 `dicodeCodex.codexPath` 或登录后安装」。此时列表退化为目录扫描（`scope` 按位置推断、`enabled` 未知），**启停不可用**并给出原因——启停依赖 `skills/config/write`，这是 CLI 缺失时唯一降级的能力。
5. 前置验证见阶段 1；不可行则退化为自行扫描技能目录 + 写用户级配置，并在此记录差异。

### 9.2 导入（文件夹 + zip）

导入入口只出现在【已安装】页签，市场页签不设导入。点击后先让用户选择「从文件夹导入」或「从 ZIP 导入」，两者共用同一套校验与落盘逻辑。

**共用校验**

- 必须包含 `SKILL.md`，frontmatter 含 `name`、`description`。
- 拒绝符号链接、加密条目、绝对路径、含 `..` 的路径。
- 目录名取源文件夹名（文件夹导入）或包内技能根目录名（zip），按 5.5 校验合法性，不做大小写折叠与字符替换。
- 重名时由用户当场决定：覆盖 / 重命名 / 取消。市场安装是无人值守流程，同名一律阻断（见 8.3），两者策略不同是有意为之。唯一例外：目标目录属于市场安装项时**不提供覆盖选项**，直接阻断并提示先删除市场版本或改名导入。
- 覆盖 `source: import` 的同名项按 8.3 提示后覆盖，不静默改写身份；目标为市场安装项一律阻断（见 8.3）。

**zip 专项**

- 仅支持 store 与 deflate，解析时校验 CRC 与声明大小，不信任压缩包头部的解压后体积。
- 限制：压缩包 ≤ 20 MB、解压后总量 ≤ 100 MB、文件数 ≤ 500、单文件 ≤ 10 MB，超限直接拒绝（`ARCHIVE_TOO_LARGE`）。
- 解压到目标同级的临时目录，校验通过后再 `rename` 到 `<workspace>/.agents/skills/<目录名>`；失败清理临时目录，不动已安装版本。
- 兼容 zip 内只有一层根目录的结构并自动剥离；多层或直接放在根部的，按 `SKILL.md` 所在目录为技能根。
- 解析器自研，只依赖 Node `zlib`，不给扩展宿主新增运行时依赖。

**落盘与登记**

- 覆盖前先备份到 `<dir>.bak`，失败还原并保留原版本。
- 成功后写 `source: import` 的登记记录，并调用 `skills/list`（`forceReload: true`）刷新索引；刷新失败标 `indexStale`。
- 导入过程显示进度；成功后刷新列表并提示，可跳转详情。
- 本地导入项的 `version` 记为 `0.0.0-local`，`dirDigest` 取目录内容 sha256，用于判断是否被外部改动。

### 9.3 删除

- 删除前模态确认，显示将删除的目录；手工放置项额外提示「该目录不在安装登记中，可能是团队共享文件」，需二次确认。
- 允许删除 `user` / `repo` 来源与 `source: market|import` 的登记项；`system` / `admin` 只读。
- 用 `workspace.fs.delete(..., { useTrash: true })`，同步移除登记记录，并推送一次 `installedSkills`。
- 删除市场安装项后，市场【全部】页签中该技能回到【安装】，不需要重新拉取远程目录。
- 删除后回列表并刷新。

### 9.4 启停

乐观更新 + 逐项 pending + 失败回滚并显示原因；刷新失败保留上一次有效数据。CLI 不可用时开关置为禁用并显示原因（9.1）。

## 12. 测试与验收

### 12.1 分阶段测试清单

**阶段 0**

- 登记原子写、并发短锁、损坏文件留 `.bak` 后可继续读；
- 状态推导覆盖五态；`compareVersion` 对预发布与多位版本号正确；
- 目录名校验：拒绝 `..`、路径分隔符、Windows 保留名、隐藏名；
- 任务日志写入后重放，非终态置 `INTERRUPTED`；锁心跳超时判定与过期清理。

**阶段 1**

- 导航改造后四项入口可用；进入市场再回对话，输入中草稿保留；
- 未登录 `listSkills` 返回本地技能且不触发 `accessToken`；
- 【已安装】页签按 `dir` 归并三类来源：市场安装、本地导入、手工放置各一条，标签与可操作项符合 9 节表格；
- 登记有而目录无标 `missing`，目录有而登记无标 `external`，两种项都不被隐藏；
- `altered` 只作附注，不改变已安装状态；
- 本页签不发起任何远程请求（`marketList` / `marketDetail` 调用次数为 0）；
- 详情读取的路径安全（拒绝 `..`、绝对路径、符号链接逃逸）；
- 文件夹导入成功、同名覆盖/重命名/取消，失败不破坏已有技能；
- 导入目标为市场安装项时被阻断，提示先删除市场版本，不写登记、不动文件；
- 「已启用」筛选可用；
- zip 导入成功、单层根目录自动剥离；
- zip 路径穿越、符号链接、加密条目、超限包被拒绝且清理临时目录；
- 导入后写入 `source: import` 登记，列表与离线可用同时生效；
- `reimportSkill` 保持原 `source` 与 `skillId`；`unregisterSkill` 不动文件；
- 删除 `system` / `admin` 被拒；删除 `import` 项同步清登记；删除手工放置项需二次确认且不写登记；
- 启停失败回滚；CLI 缺失时启停禁用并提示。

**阶段 2**

- 搜索命中名称/简介/标签；两页签切换后各自状态保留；
- 【全部】的「已安装」标记只认 `source: market` 且 `skillId` 命中；同名本地导入项不显示为已安装，而是附注「本地已有同名技能」；
- 未登录进入市场落到【已安装】页签，切到【全部】显示登录引导而不是错误态；
- 五态按钮文案与禁用状态（按 5.4 映射表逐条核对）；在途状态不可重复点击；
- 骨架、错误、空态、缓存过期标注、离线已安装；
- 最小化/最大化切换后市场状态保持；
- 四套主题下状态色可辨识。

**阶段 3**

- 连续三次安装同一版本只产生一个 `jobId`；
- 第二个窗口在同一工作区发起同一安装，接入同一条任务、不重复写目录；
- 摘要不一致、来源校验失败、不兼容、组织限制四类均不写登记；
- 同状态下连续进度事件按 `seq` 全部生效，重复 `seq` 被忽略；
- 覆盖安装成功换版本；中途失败回滚且登记不变；
- 详情页发起更新（目录项有更高版本）：走同一覆盖管道，成功后登记版本递增、卡片附注消失；失败回滚且旧版本仍可用；
- 目标目录被其他 `skillId` 或手工放置的目录占用时报 `DIR_CONFLICT`，不写入、不改名；
- 锁心跳中断 30 秒后可被接管；锁未失效时等待超时报 `LOCK_TIMEOUT`；
- 扩展重启后中间态转 `INTERRUPTED` 并可重试，临时目录被清理；
- 索引刷新失败标 `indexStale` 并可重试；
- 安装成功后【已安装】页签立即出现该项、【全部】卡片转【已安装】，删除后【全部】卡片回到【安装】，两个方向都不需手动刷新；
- 安装完成后不重启，`skills/list` 能命中新技能（对应 PRD「调用」）。

**阶段 4**

- 真实目录分页、超时、离线回退；
- 鉴权失效后引导重新登录；
- 错误码与服务端一致；缓存分组淘汰生效。

## 13. 已确认决策

| # | 事项 | 决策 |
| --- | --- | --- |
| 1 | 设计稿缺口 | 按需求先实现。版本、简介、兼容状态在 UI 出稿前留空态兜底；详情页按需求字段自行排版，不等稿。已安装详情的「声明能力/示例」本地无结构化来源，显示空态并注明由市场提供 |
| 2 | 登记文件 | 位于用户工作区，不入库。扩展不静默改用户 `.gitignore`，首次写入时检测并提示一次、提供确认动作。团队共享「该装哪些技能」另出只含 `skillId` 与版本的推荐清单 |
| 3 | 安装目录命名 | 取**来源目录名**（导入＝源文件夹名，市场＝包内技能根目录名），不加发布者前缀与版本后缀；不合规则拒绝而非静默改名；同名冲突报 `DIR_CONFLICT` |
| 4 | 目录缓存 | 全局 `globalStorageUri`，跨工作区共用，按 `q` + `filter` 分组，20 组 / 2 MB 上限 + LRU 淘汰 |
| 5 | `INTERRUPTED` | 先用本地自定义码，阶段 4 若服务端有对应码再映射 |
| 6 | 发布节奏 | 阶段 3 收尾发一版内测 VSIX（桩数据模式），阶段 4 联调通过后发正式版 |
| 7 | 市场页结构 | 【全部】与【已安装】是两个页签，不是同一列表的过滤条件。【全部】请求远程、由服务端筛选；【已安装】即本地技能管理，只读本机索引与登记，不请求远程、不依赖登录 |
| 8 | 已安装标记口径 | 只认登记中 `source: market` 且 `skillId` 命中的记录；本地导入或手工放置的同名技能不算已安装，卡片附注「本地已有同名技能」 |
| 9 | 手工放置项 | 不写登记，在【已安装】页签以 `external` 展示，可启停与查看详情，删除需二次确认 |
| 10 | 默认页签 | 已登录进【全部】，未登录进【已安装】，保证未登录也能管理本地技能 |
| 11 | 导航入口 | 「左上导航四项 + 左下用户中心/设置」由本模块在阶段 1 前置完成，不改布局开关 |
| 12 | UI 组件库 | 不引入 `@dicode/webview-ui`，市场与已安装两页均自研，视觉对照原型取值；后续要接入时按组件 props 形状留适配点 |
| 13 | CLI 侧安装 | 不在本模块职责范围，不排期、不验收、不做复用契约、不对齐终端团队；本模块只交付扩展侧链路 |
| 14 | 事件与任务持久化 | 事件按 `jobId` + `seq` 幂等；任务日志与目录锁存 `globalStorageUri`，不写进工作区 |
| 15 | 版本更新呈现 | 按 PRD 五态，列表不新增「可更新」按钮；登记版本落后时卡片附注 + 详情页更新入口，随阶段 3 交付，复用覆盖管道 |
| 16 | 既有能力保留 | 保留「已启用」筛选、文件夹导入、同名覆盖/重命名/取消的交互 |
